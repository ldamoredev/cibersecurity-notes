# Source policy

Use primary specifications, maintained project documentation, standards bodies,
and primary incident reports before secondary explanations. Record version and
verification date when a claim depends on a changing document.

Preferred anchors include NIST CSF/SSDF, CISA Secure by Design, OWASP ASVS,
WSTG and API Security, IETF RFCs and browser specifications, MITRE ATT&CK and
D3FEND, Sigma, YARA, Zeek, Suricata, osquery, SLSA, Sigstore, SPDX,
CycloneDX, Kubernetes documentation, cloud-provider security documentation,
and OWASP/MITRE/NIST AI security guidance.

Do not treat SEO content, social posts, tool rankings, a scanner result, or an
ATT&CK mapping as proof of security coverage. Mitigations reduce risk; they do
not erase residual risk without verification.
